# قالب مستقل فضای کاری نوژان

قالب فارسی RTL بر پایه Next.js، React، Prisma و MySQL، برای **پروژه جدید و دیتابیس اختصاصی خالی**. کاربران، نقش‌ها، ورود، وظایف، تاریخچه وظایف و اعلان‌ها حفظ شده‌اند. ماژول‌های کالا، دسته‌بندی، سفارش و درخواست پرسنلی حذف شده‌اند. AI Import و Roadmap مبتنی بر SQLite جزو این بسته نیستند.

## وضعیت تحویل

این نسخه برای بازبینی است، نه استقرار تأییدشده. نصب وابستگی‌ها در محیط آماده‌سازی با `ECONNRESET` متوقف شد؛ Prisma validate/generate، typecheck، build، smoke، migration واقعی و آزمون مرورگر اجرا نشده‌اند. گزارش دقیق در `AUDIT.fa.md` است. موفقیت آزمون آفلاین، صحت SQL یا خالی‌بودن دیتابیس را اثبات نمی‌کند.

## پیش‌نیاز

- Node.js حداقل 22.12 و npm، اینترنت برای `npm ci`.
- MySQL 8، دیتابیس تازه با utf8mb4 و حساب اختصاصی؛ هرگز دیتابیس اصلی نوژان یا دیتابیس دارای داده را انتخاب نکنید.
- اجرای دائمی سرور Node.js؛ برنامه خروجی استاتیک نیست.
- PowerShell برای ویندوز یا Bash برای لینوکس/WSL.

ZIP را در پوشه جدید استخراج کنید. نصب‌کننده تک‌فایلی نسخه اصلی متعلق به این قالب نیست. نسخه‌های وابستگی تغییر نکرده‌اند.

## تنظیم و نصب

مدیر زیرساخت باید ابتدا دیتابیس **خالی و اختصاصی** و اعتبارنامه محدود به آن را بسازد. حساب migration به مجوزهای DDL لازم و حساب runtime فقط به مجوزهای مورد نیاز برنامه نیاز دارد. حساب root یا اعتبارنامه محیط اصلی را استفاده نکنید.

نصب محلی (این فرمان‌ها به دیتابیس متصل می‌شوند و پس از تأیید جدول و مدیر می‌سازند):

```bash
bash setup.sh test
# فقط پس از نصب کامل وابستگی‌ها:
bash setup.sh test --skip-install
```

```powershell
.\setup.ps1 -Mode test
# فقط پس از نصب کامل وابستگی‌ها:
.\setup.ps1 -Mode test -SkipInstall
```

برای استقرار از حالت صریح `production` استفاده کنید. نصب، `.env` موجود را حفظ می‌کند. فرم تنظیمات نام دیتابیس جدید می‌خواهد؛ نام‌های پروژه اصلی مسدودند. `.env.example` صرفاً نمونه است و رمز معتبر ندارد.

مقادیر `FRESH_DB_MODE` و `FRESH_DB_HOST/PORT/NAME` باید دقیقاً با حالت فرمان و `DATABASE_URL` منطبق باشند. در حالت test تنها loopback مجاز است. `SESSION_SECRET` تصادفی حداقل ۳۲ نویسه و در production مقدار `COOKIE_SECURE=true` و HTTPS لازم است.

فرمان‌های مستقل:

```bash
npm ci
npm run setup:env -- test
npm run db:check -- test     # فقط بررسی آفلاین؛ بدون اتصال
npm run db:generate
npm run db:deploy -- test    # نیازمند تأیید؛ اتصال و migration
npm run db:admin -- test --if-missing  # نیازمند تأیید؛ ایجاد مدیر
npm run typecheck
npm run build
npm start -- --hostname 127.0.0.1
```

در PowerShell در صورت مشکل سیاست اجرای npm از `npm.cmd` استفاده کنید. برای توسعه `npm run dev` موجود است.

## محافظ نصب و محدودیت‌های آن

- `db:check` فقط تنظیمات و وجود baseline محلی را بررسی می‌کند؛ هویت واقعی سرور، خالی‌بودن دیتابیس و صحت schema را تأیید نمی‌کند.
- پیش از هر عملیات متصل، باید رشته دقیق `mode:host:port/database` را تأیید کنید. برای اجرای غیرتعاملی، `FRESH_DB_APPROVAL` را فقط در محیط همان پردازش تنظیم کنید؛ مقدار داخل `.env` مجوز اتصال محسوب نمی‌شود.
- پس از تأیید، محافظ جدول‌ها، اشیای اضافی و تاریخچه migration را فقط‌خواندنی بررسی می‌کند. تنها دیتابیس خالی اجازه migration اولیه می‌گیرد.
- baseline تکمیل‌شده با نام/checksum درست و مجموعه جدول مورد انتظار، نصب قبلی همین قالب محسوب می‌شود و migration تکرار نمی‌شود. این بررسی **ممیزی کامل drift ستون‌ها و ایندکس‌ها نیست**.
- دیتابیس ناشناخته، migration ناقص یا تاریخچه ناسازگار مسدود می‌شود؛ reset، repair، retry یا baseline کردن دیتابیس موجود انجام نمی‌شود.
- مهاجرت شامل چهار جدول برنامه (`users`, `tasks`, `task_events`, `notifications`) است؛ Prisma جدول `_prisma_migrations` را مدیریت می‌کند. SQL اولیه هنوز با Prisma یا MySQL اعتبارسنجی نشده است.
- نصب‌کننده‌های هم‌زمان را متوقف کنید. بررسی هویت سرور/DNS، TLS، مجوز استقرار و جداسازی حساب‌ها مسئولیت اپراتور است. محافظ جایگزین کنترل دسترسی دیتابیس نیست؛ اجرای مستقیم Prisma آن را دور می‌زند.
- `db:studio -- test|production` نیز نیازمند تأیید است؛ Studio امکان نوشتن دارد.

## آزمون‌ها و امنیت

`npm run test:offline` بدون وابستگی خارجی و بدون دیتابیس اجرا می‌شود. `npm run test:smoke` بعد از build، بررسی محدود HTTP بدون ورود معتبر است؛ CRUD را نمی‌آزماید. برنامه پذیرش در `TESTING.fa.md` آمده است.

رمز مدیر پیش‌فرض وجود ندارد. نشست و رمزها را در مخزن یا ZIP نگذارید. برای شبکه از HTTPS، reverse proxy، محدودسازی درخواست و پشتیبان‌گیری استفاده کنید. خطای `ECONNRESET` را با اصلاح شبکه رفع کنید، نه غیرفعال‌کردن TLS. در خطای migration توقف و بررسی دستی لازم است؛ هیچ‌گاه برای رفع نصب روی داده واقعی reset یا حذف جدول انجام ندهید.
